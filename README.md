# 和鸣 · Hermes 渠道插件

通过二维码将自己的 Hermes 智能体连接到和鸣。模型和工具沿用 Hermes 原有设置；和鸣只负责个人专属会话，不要求填写平台 Token、Webhook 或流式输出选项。

本仓库只分发 Hermes 插件，不包含和鸣客户端、服务器后端或任何用户数据。完整产品源码不在此公开。

**当前插件版本：0.1.6。** 新增通用文件回传，不限定文件后缀；只负责传送和下载，不负责打开、预览、解析或转换。已有连接更新后无需重新扫码。当前和鸣 Android 4.2.3 可接收文件，本次不另发 App 版本。

## 安装

需要已有可用的 Hermes、Git，以及 PATH 中的 Node.js 24 或更新版本。Hermes 平台插件接口以官方 v0.22.2 验证；不承诺兼容任意旧版本。

```bash
hermes plugins install Kunvis-lab/heming-hermes --no-enable && hermes plugins enable heming
```

Hermes 可能要求确认第三方插件安全检查，请阅读提示后决定是否继续。不要跳过安全检查。安装包已包含连接器依赖，不需要运行 npm install。

随后执行：

```bash
hermes gateway setup
```

选择“和鸣 · 扫码连接”后，直接在当前终端显示二维码并等待扫码。完成配对后回到菜单，和鸣才显示为 `configured`；这代表配对信息已保存，不代表 Gateway 当前在线。已有 Gateway 服务时运行 `hermes gateway restart`；没有运行 Gateway 时可执行 `hermes gateway run` 前台启动。不要在同一 profile 中同时启动两个 Gateway。插件与 Gateway 必须使用相同的系统账号及 Hermes profile（自定义 HERMES_HOME 时同样如此）。

## 扫码连接

1. 在 `hermes gateway setup` 中选择和鸣，当前终端立即显示有效期 10 分钟的新增连接二维码。0.1.5 保留原有连接；已有用户更新后无需重新扫码，需要添加下一位成员时才再次扫码。
2. 使用支持智能体功能的和鸣客户端，进入“消息 → ＋ → 扫一扫”，自动识别智能体二维码。
3. 输入机器人名字，点击“创建并添加”，加入通讯录并自动进入专属会话。连接信息和解除连接在机器人联系人详情的“更多”中，不在个人页单设菜单。
4. 发送文字或 Markdown；普通回答完成后直接显示结果，不展示思考过程。重启后复用已有身份，无需重复扫码。

### 多成员连接（0.1.5）

同一 Hermes profile 支持多位成员独立连接。再次在 `hermes gateway setup` 选择和鸣会显示新增连接二维码，不覆盖旧身份；由对应成员用自己的和鸣扫码。已运行的 Gateway 自动加载新连接，原成员不必重新扫码或退出。聊天、卡片归属和任务操作台账按连接保存，未知收件目标不会回退到第一个成员。

团队仍共用 Hermes 的模型、工具、文件及安全策略，不是强租户隔离。需要严格隔离文件或工具权限时，应使用独立 profile／运行环境。

### 真实任务管理（0.1.5）

在和鸣 Android 3.6.0 的机器人聊天顶栏点时钟进入「定时任务」，支持指定未来时间一次执行、周期执行与后台任务；普通问答不进入任务清单。

- 创建、编辑、暂停后续计划、恢复、立即执行、失败后重新执行及查看真实执行记录，操作由智能体确认后才生效。
- 详情分别展示执行计划、下次时间、本次状态与 Markdown 结果；结果可复制、收藏和分享，较长输出明确标注同步上限。
- 「停止本次」等待原生 worker 确认，保留下次安排；「结束整个任务」撤销后续计划，运行中先显示正在停止。停止不能回滚外部操作，原生检查可能需要约一分钟。
- 周期按页面标注的智能体时区运行；复杂原生脚本或高级周期配置在智能体端管理，不误转为普通提示词。主机和 Gateway 需要保持运行。
- 任务控制走现有加密通道，不新增服务器明文任务接口；遵循 Hermes 原有模型、工具和批准策略。

### 批准请求（0.1.3）

智能体需要执行由 Hermes 判定须批准的操作时，和鸣显示独立批准卡片，而不是隐藏在工具进度中。核对内容后可允许一次或拒绝；只有 Hermes 本身允许时才展示其他允许范围，持续授权需再次确认。超时不代表同意，旧请求和重复点击不能批准其他操作。模型、工具执行和永久允许列表仍由 Hermes 管理，不由插件绕过安全限制。

命令批准请使用和鸣 Android 3.2.0 或以上版本。更旧客户端只能看到文本摘要，没有可用的批准按钮。命令批准已通过真实 Hermes v0.22.2 隔离运行时、加密传输及真实手机的“拒绝”和“允许一次”闭环。

机器人直接反馈，不自动引用你的上一条消息。已配对的个人会话会自动成为和鸣默认会话，不要求输入 `/sethome`；已有的显式默认会话或禁用设置不会被覆盖。工具过程提示不拼进最终反馈，真实失败仍会明确显示。

### 资料继续加工与任务交互（0.1.4）

**配套版本：和鸣 Android 3.4.0 + 本插件 0.1.4。** 仅更新 App 或仅更新插件，不能完整使用本次功能。已有安装请运行 `hermes plugins update heming`，再运行 `hermes gateway restart`，让同一 profile 的 Gateway 加载新版；不删除身份、不要求重新扫码。

- 在资料详情点击“继续加工”，回到原机器人会话；资料以独立 Markdown 快照放入输入区，可先预览或移除。输入要求并点击发送后才开始，新答复不会自动覆盖原资料。
- Hermes 原生 clarify 追问可在聊天内单选、多选或补充文字；单选点选即提交，多选需确认。过期和结束的问题不能再次作答。
- 任务显示处理中、等待补充和真实终态；“停止处理”经 Hermes 正常停止路径确认，不等于撤销已经执行的工具操作。失败不自动重跑，需用户核对并重新发送。
- 普通答复仍只展示最终结果；思考、工具过程和模型配置不进入正文。状态更新不额外计为未读消息。

资料继续加工、原生追问回答和生成中停止已在真实 Hermes v0.22.2 与测试手机联调；命令批准沿用现有安全边界。安装成功不代表当前 Gateway 已在线，第三方模型和工具能否正常工作仍取决于你的 Hermes 配置。停止不能回滚外部操作，也不承诺 Gateway 进程退出后模型任务能继续运行。

0.1.6 支持文字、Markdown，以及机器人向配对者回传文件；不支持手机向机器人发送附件，也不支持机器人语音或视频通话。默认仅扫码授权的本人可使用，不开放其他人通过 ID 添加或加入群聊。

### 文件回传（0.1.6）

Hermes 生成的本地文件可以作为普通附件发回和鸣。不限定 DOCX、XML、HTML 等后缀；这些只是示例，不是支持格式清单。图片、音视频和没有后缀的文件也按普通附件传送，插件不会打开或转换它们。和鸣官方服务已部署配套接口；自建后端需先更新兼容的机器人附件接口。

使用时可以直接说：“生成一份调研报告，以文件发给我。”Hermes 需实际生成文件再提交发送；只返回服务器路径、链接文字或代码块，不代表文件已送达。收到文件卡片后可下载，是否打开及如何处理由用户和手机上的其他应用决定，不属于插件能力。

模型或工具应在单独一行输出 `MEDIA:绝对路径`；路径含空格时使用 `MEDIA:"绝对路径"`。不要把发送标记放进代码块或示例。插件不抓取任意 URL，不扫描目录，不替 Hermes 安装文件生成工具。文件内容是否正确、安全，仍由文件生成者及使用者判断。

每个文件最多 100 MiB，空文件不能发送。文件端到端加密，投递检查点支持断线重试和去重；凭据、身份目录、系统敏感路径及特殊文件仍受限制，去掉格式限制不等于允许任意读取。文件、工具权限仍受所在 Hermes 环境约束，多成员连接不是文件系统强隔离。请勿运行不信任的附件。

## 更新

```bash
hermes plugins update heming
```

更新后执行 `hermes gateway restart`。身份和会话状态保存在当前 Hermes profile 的 `heming/` 目录中，不在插件安装目录中；不要删除该目录、卸载 Hermes profile 或把身份文件上传到 GitHub。升级前建议自行安全备份整个 Hermes profile。

### 从旧安装来源迁移

新安装统一使用本页的 `Kunvis-lab/heming-hermes`。旧安装的 `update` 仍跟随原来的 Git 来源，不会自动切换。先停止当前 Gateway 并安全备份当前 profile，再依次运行：

```bash
hermes plugins remove heming
hermes plugins install Kunvis-lab/heming-hermes --no-enable
hermes plugins enable heming
```

这只更换插件目录；不要删除当前 profile 的 `heming/identity.json`，否则会丢失配对。完成后启动 Gateway，复用原机器人身份。请正常阅读安装安全提示，不使用跳过检查的选项。

## 安全与隐私

- 机器人是独立的端到端加密终端，身份私钥在运行 Hermes 的机器生成并保存。二维码不包含长期凭证或私钥。
- 插件只访问绑定的个人会话，不读取其他和鸣聊天。解除连接后，旧凭证停止使用。
- 主动发给机器人的内容会在 Hermes 主机解密，并可能交给 Hermes 配置的模型和工具；适用所选模型服务的数据处理规则。
- 插件运行在 Hermes 的权限范围内。仅在自己信任的机器和 Hermes 环境安装，不要将主机执行权限开放给陌生人。
- 保持 TLS 证书校验开启。无需修改防火墙入站规则，无需公开本机端口，也不要设置 NODE_TLS_REJECT_UNAUTHORIZED=0。

## 排查

- 找不到 node：安装 Node.js 24+，确认 Gateway 的运行账号能够执行 `node --version`；终端与系统服务的 PATH 可能不同。
- 看不到和鸣渠道：执行 `hermes plugins list` 检查 heming 是否已启用，确认使用正确的 profile，然后重新执行 gateway setup。
- 二维码没出现：检查 Node、网络，以及服务器是否已上线智能体配对接口；配对票据会过期，过期后重新选择和鸣扫码。若提示另一个配对进程正在运行，先在原窗口完成或取消它，不删除身份或正在使用的锁文件。旧版插件只会在 Gateway 输出中展示二维码，需更新插件以使用配置菜单扫码。
- 已连但没有回复：检查 Hermes 原有模型是否可用、Gateway 日志及和鸣兼容版本。不需要把模型密钥提供给和鸣。

可以用 `sha256sum -c SHA256SUMS` 检查下载文件的一致性（macOS 使用 `shasum -a 256 -c SHA256SUMS`）。校验文件本身不是数字签名，应同时确认仓库来源和可信版本。
